# Match Explanations

**"What caught our eye"** — the AI-generated explanation shown on every Moments card. It tells users WHY they're being matched with this specific person, using real behavioral data.

---

## What is a match explanation?

Every user-candidate pair in the daily deck gets a personalized explanation generated by ECHO (via OpenAI). This explanation appears on the Moments card BEFORE any choice is made.

**Components:**
1. **Headline** — 1 sentence (max 15 words), e.g., "You both want something that can grow, with an easy pace."
2. **Bullets** — 1-2 bullet points (max 20 words each), e.g., "Shared: similar approach to health + routines"
3. **Tone** — playful, calm, or serious (determined by viewer's pulse vector)
4. **Bridge question** — Opening question pre-loaded into chat if they match
5. **Date ideas** — 3 specific date ideas (hidden until Find Love unlocks)

**Table:** `match_explanations`

---

## Generation flow

**When:** During daily deck build (`DailyDeckOrchestrator.BuildDeckAsync()`)

**For each user-candidate pair:**
1. Load `PairContext` (shared tags, aligned pillars, hobbies, tone match)
2. Load viewer's behavioral feedback (tone bias, date style hints)
3. Extract match reasons from `MatchScore` and vectors
4. Determine tone from viewer's pulse vector
5. Call OpenAI to generate explanation JSON
6. Save to `match_explanations` table
7. Link to `DailyDeckItems` via `ExplanationId`

**Service:** `backend/WovenBackend/Services/Matchmaking/MatchExplanationService.cs`

## Tone determination

**Three tones:** playful, calm, serious

**Logic:**
```csharp
private string DetermineTone(string vectorJson)
{
    var pulse = ExtractPulseFromVector(vectorJson);
    var socialCapacity = pulse["socialCapacity"];

    if (socialCapacity > 0.7) return "playful";
    if (socialCapacity < 0.4) return "serious";
    return "calm";
}
```

**Tone bias (behavioral feedback):**
- ECHO tracks which explanations led to fast contact (messages within 48h)
- If ≥50% of fast contacts came from one tone (min 3 contacts) → tone bias detected
- Future explanations for this viewer lean into that tone

**Example:**
> User historically messages faster when explanations are playful → ECHO generates playful explanations more often.

## PairContext integration

**What is PairContext?**
A rich data structure containing:
- `SharedTags` — interests both users have in common
- `AlignedPillars` — AI Profile pillars where scores are similar
- `SharedHobbies` — hobbies both users mentioned
- `ToneAlignment` — how well their communication styles match
- `IntentAlignment` — high/medium/low based on intent score

**Service:** `backend/WovenBackend/Services/IAiProfileService.cs`

**How it's used:**
```csharp
var pairContext = await _aiProfileService.GetPairContextAsync(userId, candidateId, ct);

var matchDataSection = $@"
MATCH DATA (USE THIS - IT'S SPECIFIC TO THESE TWO PEOPLE):
- Shared interests/tags: {string.Join(", ", pairContext.SharedTags)}
- Aligned traits: {string.Join(", ", pairContext.AlignedPillars.Select(p => p.Pillar))}
- Shared hobbies: {string.Join(", ", pairContext.SharedHobbies)}
- Tone match: {pairContext.ToneAlignment}
- Intent alignment: {pairContext.GetIntentAlignmentDescription()}
";
```

**This data is passed to OpenAI** so explanations reference ACTUAL shared interests, not generic compatibility.

## Behavioral feedback loop

**Two types of feedback:**

### 1. Tone bias

**What:** Which tone led to fastest contact (messages within 48h)?

**Query:**
```csharp
// Find candidates where viewer messaged within 48h
var fastContactIds = await db.MatchSignalLogs
    .Where(s => s.ViewerId == userId
             && s.EventType == "TimeToFirstMessageMs"
             && s.EventValue < 172_800_000L)  // 48h in ms
    .Select(s => s.CandidateId)
    .Distinct()
    .ToListAsync();

// Find tone of those explanations
var tones = await db.MatchExplanations
    .Where(e => e.UserId == userId && fastContactIds.Contains(e.CandidateId))
    .Select(e => e.Tone)
    .ToListAsync();

// Find dominant tone (≥50% threshold, min 3 contacts)
var dominant = tones.GroupBy(t => t).OrderByDescending(g => g.Count()).First();
if (dominant.Count() * 2 >= tones.Count && tones.Count >= 3)
    return dominant.Key;  // "playful", "calm", or "serious"
```

**Used in prompt:**
```
VIEWER HISTORY:
- This viewer connects faster when tone is playful — lean into that
```

### 2. Date style hints

**What:** Which date ideas has this viewer chosen in the past?

**Query:**
```csharp
var signals = await db.MatchSignalLogs
    .Where(s => s.ViewerId == userId && s.EventType == "DateIdeaAccepted")
    .OrderByDescending(s => s.OccurredAt)
    .Take(5)
    .Select(s => s.MetadataJson)
    .ToListAsync();

// Extract "chosenIdea" from JSON
var ideas = signals
    .Select(m => JsonDocument.Parse(m).RootElement.GetProperty("chosenIdea").GetString())
    .Where(s => !string.IsNullOrEmpty(s))
    .ToList();

return string.Join("; ", ideas);
```

**Used in prompt:**
```
VIEWER HISTORY:
- This viewer has previously chosen: Coffee date; Bookstore wandering; Park walk
  → offer variety but lean toward that style
```

## OpenAI prompt structure

**System prompt:**
```
You write 'why you're a match' explanations for a dating app.

Tone: {tone}

MATCH DATA (USE THIS - IT'S SPECIFIC TO THESE TWO PEOPLE):
- Shared interests/tags: photography, hiking, jazz
- Aligned traits: Energy, Curiosity
- Shared hobbies: weekend runs, cooking
- Tone match: high
- Intent alignment: both want long-term, exclusive

VIEWER HISTORY (personalize for this specific viewer):
- This viewer connects faster when tone is playful — lean into that
- This viewer has previously chosen: Active outdoor dates — lean toward that style

STRICT REQUIREMENTS:
- Write 1 headline (max 15 words) - MUST reference at least 1 aligned trait OR 2 shared interests
- Write 1-2 bullet points (max 20 words each) - MUST mention specific shared interests/traits
- Write 3 date ideas (max 15 words each):
  * One active/outdoor activity
  * One social/cultural activity
  * One casual/low-key activity
  * If they share hobbies, at least 1 idea MUST incorporate one
  * No overlap in activity type across the 3
- Write 1 bridge question: an opening question specific to this pair
  * Rooted in something real from match data
  * Invites a story or memory, not yes/no
  * Max 20 words
  * Natural and warm
  * NOT generic — must be specific to this pair

BANNED PHRASES (NEVER USE):
- 'good energy'
- 'meaningful connection'
- 'real conversations'
- 'authentic'
- 'genuine'
- 'vibe'
- 'worth exploring'
- 'something special'

USE THEIR ACTUAL DATA - be specific, not generic!

Output ONLY valid JSON:
{
  "headline": "You both [specific shared trait/interest]...",
  "bullets": [
    "[Specific shared interest]: [what you have in common]",
    "[Aligned trait]: [how you're similar]"
  ],
  "dateIdeas": [
    "[Active/outdoor idea using their shared interest]",
    "[Social/cultural idea]",
    "[Casual/low-key idea]"
  ],
  "bridgeQuestion": "[Specific opening question for this pair]"
}
```

**User prompt:**
```
Match reasons: {
  "bucket": "CORE_FIT",
  "totalScore": 85,
  "sharedTags": ["photography", "hiking", "jazz"],
  "alignedPillars": [
    {"pillar": "Energy", "avgScore": 0.78},
    {"pillar": "Curiosity", "avgScore": 0.82}
  ],
  "sharedHobbies": ["weekend runs", "cooking"],
  "toneAlignment": "high",
  "intentAlignment": "both want long-term, exclusive"
}

Generate explanation JSON. Be SPECIFIC using the match data provided.
```

## Database schema

**Table:** `match_explanations`

```sql
CREATE TABLE match_explanations (
    id SERIAL PRIMARY KEY,
    user_id INT NOT NULL,           -- Viewer (who sees the explanation)
    candidate_id INT NOT NULL,      -- Match candidate
    date_utc DATE NOT NULL,         -- Matches DailyDeck date
    headline VARCHAR(200) NOT NULL,
    bullets_json TEXT NOT NULL,     -- JSON array of strings
    tone VARCHAR(20) NOT NULL,      -- "playful", "calm", "serious"
    date_idea VARCHAR(200),         -- Legacy single idea
    date_ideas_json TEXT,           -- JSON array of 3 ideas
    bridge_question VARCHAR(200),   -- Opening question
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    INDEX idx_user_candidate_date (user_id, candidate_id, date_utc)
);
```

## Personalization layers

**Layer 1: PairContext (match-specific)**
- Shared tags from orbits/dwell interactions
- Aligned AI Profile pillars
- Shared hobbies from foundational answers
- Tone alignment score
- Intent alignment description

**Layer 2: Behavioral feedback (viewer-specific)**
- Tone bias from past fast contacts
- Date style hints from past date idea choices

**Layer 3: Bucket-specific templates (fallback)**
- CORE_FIT, LIFESTYLE_FIT, CONVERSATION_FIT, EXPLORER, WILDCARD
- Used only when OpenAI fails or vectors are missing

**Result:** Every explanation is unique to the viewer-candidate pair AND personalized to the viewer's past behavior.

## Quality metrics

**How we measure explanation quality:**

1. **Fast contact rate** — % of viewers who message within 48h
2. **Choice rate** — % of viewers who choose MAGICAL or RESONANT (vs PASS)
3. **Specificity score** — manual audit: does explanation reference actual shared data?
4. **Tone match accuracy** — does generated tone match viewer's pulse vector?

**Logged per explanation:**
- `MatchExplanation.Id` → linked to signals via `CandidateId` + `DateUtc`
- `MatchSignalLog.EventType = "TimeToFirstMessageMs"` → outcome proxy
- `MatchSignalLog.EventType = "ChoiceMade"` → action taken (MAGICAL/RESONANT/PASS)

## Bridge question mechanics

**What:** Opening question pre-loaded into chat if match is created.

**Requirements:**
- Rooted in real match data (shared tag, pillar, hobby)
- Invites story or memory (not yes/no)
- Max 20 words
- Natural and warm

**Example:**
> **Bad:** "Do you like jazz?"  
> **Good:** "What's a jazz album that stuck with you the first time you heard it?"

**Storage:**
- `match_explanations.bridge_question` (varchar 200)
- Shown on Deck card after user makes choice
- Pre-loaded into chat as suggested opener if match is created

**See:** [bridge-questions.md](./bridge-questions.md) for full details.

## Date ideas mechanics

**3 date ideas per explanation:**
1. Active/outdoor activity
2. Social/cultural activity
3. Casual/low-key activity

**If shared hobbies exist:** At least 1 idea MUST incorporate a shared hobby.

**Example (shared hobby: cooking):**

"dateIdeas": [

**Unlock timing:**
- Hidden until Find Love unlocks (`FindLoveAt <= now`)

## Error handling

**If OpenAI call fails:**
1. Log warning with correlation ID
2. Fall back to bucket-specific template
3. Save fallback explanation to database
4. Deck build continues (no blocking failure)

**If JSON parsing fails:**
1. Log warning with raw OpenAI response
2. Fall back to bucket-specific template
3. Save fallback explanation

**If PairContext is null:**
1. Extract reasons from vectors directly (old logic)
2. Generate explanation without shared tags/hobbies
3. Explanation will be more generic but still bucket-appropriate

## Performance optimization

**Batch generation:**
- Daily deck build generates 5-15 explanations per user
- OpenAI calls are sequential (no parallel batching yet)
- Takes ~3-5 seconds per explanation

**Caching:**
- Explanations are cached in database by (user_id, candidate_id, date_utc)
- If deck is rebuilt on same day, existing explanations are reused
- No re-generation unless vectors/context change

**Future optimization:**
- Batch OpenAI calls (5-10 parallel via Task.WhenAll)
- Pre-generate explanations for top candidates overnight
- Cache PairContext to avoid repeated calculations
