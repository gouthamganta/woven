# Seed Data and Test Personas

## There is no automated seed data tooling

The Woven codebase does not include a seed script, a fixture loader, or any automated mechanism for populating test data. There is no `dotnet run -- seed` command, no `npm run seed`, and no migration that inserts sample users.

All test data must be created manually by going through the actual application flows: creating accounts, completing onboarding, interacting with cards. This is intentional — behavioral signals are generated by real interactions, and synthetic shortcuts that bypass the app's state machines would produce inconsistent data.

---

## Test personas to create

When setting up a local environment for development or testing, create at minimum three pairs of users covering the stages below. Each user must complete full onboarding before they appear in the deck.

### Pair A — Onboarding complete, no matches yet

Two users who have finished all onboarding steps and are visible in each other's decks. Use these to test:
- Deck delivery and ordering
- Card rendering (name, badge, explanation)
- Respond flow (MAGICAL / RESONANT / PASS)

Both users must have completed onboarding through the final review step and reached the main app. Neither should have responded to the other's card yet.

### Pair B — Matched, currently in trial

Two users who have both responded positively to each other's cards, submitted their notes (20–150 characters), had a match created, and both opened the chat thread so that `TrialEndsAt` is set. Use these to test:
- Trial period UI and countdown
- Voice note flow within trial
- CONTINUE / END / BLOCK decision paths
- Ghost refund logic (end trial before either sends a message)

For the trial to be active, both `TrialUserAOpenedAt` and `TrialUserBOpenedAt` must be non-null, meaning both users opened the chat after the match was created.

### Pair C — Reached Find Love stage

Two users who have matched, passed through trial with a CONTINUE decision, and both sent at least one message so that `BothMessagedAt` is set. `FindLoveAt = BothMessagedAt + 5 minutes`. After that timestamp passes, the 3 date idea cards appear. Use these to test:
- Find Love card appearance and timing
- Date idea selection (`Plan It` action)
- `DateIdeaAccepted` signal recording
- Mutual interest notification when both select

## How signals accumulate for ECHO to work

ECHO's weight learning depends on having enough training data. Two thresholds matter:

### ConnectionScore threshold — 0.08

`ConnectionScoreBatchWorker` runs at 03:50 UTC daily and aggregates behavioral signals into a `ConnectionScore` for each (viewer, candidate) pair. The minimum meaningful score is **0.08**.

A pair where only a `BalloonPopped` signal exists (weight = 0.05) scores approximately 0.05 — below the 0.08 threshold. That pair does not qualify as a training example. To produce a qualifying pair, at minimum a `TrialRequested` signal (weight = 0.10) must also be present, giving a combined score of 0.15.

In practice, a pair that went through a full trial (TrialAccepted = 0.25) or had a substantive conversation (ConversationDepth = 0.20) will comfortably exceed the threshold.

### WeightLearningBatchWorker threshold — 10 connection scores per user

`WeightLearningBatchWorker` runs at 04:00 UTC on Sundays. For a user's weights to be updated by the logistic regression, that user needs **at least 10 qualifying ConnectionScore records**. A user with fewer than 10 qualifying pairs will continue using the default weights from `appsettings.json` (the `Echo` section).

In a local environment, reaching this threshold requires creating multiple test pairs and running both batch workers manually (or waiting for their scheduled runs).

### Running batch workers manually in local development

The batch workers are hosted services registered in `Program.cs`. In a local environment, trigger them by either:
- Waiting for their scheduled times (ConnectionScore at 03:50, WeightLearning at Sunday 04:00), or
- Temporarily adjusting the schedule in code for a one-off local test run (do not commit this change).

There is no HTTP endpoint to trigger batch workers on demand.

## Signal checklist for a test pair

To produce a pair with a qualifying ConnectionScore, walk through these interactions:

| Interaction | Signal recorded | Weight |
|---|---|---|
| Match created (balloon popped) | `BalloonPopped` | 0.05 |
| One user opens trial chat | — | — |
| Second user opens trial chat | `TrialRequested` | 0.10 |
| CONTINUE decision made | `TrialAccepted` | 0.25 |
| Both users exchanged messages | `ConversationDepth` | 0.20 |
| Date idea selected | `DateAccepted` | 0.15 |

A pair that completes all of the above accumulates a ConnectionScore of 0.75 — well above the 0.08 threshold and meaningful training data for the weight learner.
