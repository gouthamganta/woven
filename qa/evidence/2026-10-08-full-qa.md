## Verified behavior and remaining findings

- A newly persisted match has expiry exactly 72 hours after creation. Candidate
  [MomentsRules.cs](https://github.com/gouthamganta/woven/blob/5461c85/backend/WovenBackend/Services/Moments/MomentsRules.cs#L7)
  implements the approved rule. Existing matches were not backfilled.
- Anonymous core requests and malformed, expired, wrong-signature and
  wrong-audience JWT probes were denied. Ordinary users could not access the
  tested admin route. A third user could not access the tested match profile
  or chat. These checks do not exhaust authorization paths.
- Founder clarified: **show both ChatNotes to the matched pair**. Both appeared
  in chat and unrelated-user access was denied. Conflicting documentation is
  queued in [#143](https://github.com/gouthamganta/woven/issues/143).
- Dedicated blocking returned success and rejected a subsequent message.
  Export succeeded once and repeated export returned 429. Production local-login
  route returned 404. An untrusted CORS origin received no allow-origin header.
- SignalR negotiation denied anonymous access and accepted an authenticated
  synthetic user. WebSocket connection and end-to-end notification delivery
  remain untested; negotiation alone does not prove delivery.
- Account deletion returned success. Its existing token then received an
  authenticated summary response. Strong account-existence/revocation enforcement
  remains unverified and is handed to Claude in
  [#108](https://github.com/gouthamganta/woven/issues/108). No other-user disclosure
  was established. Matched-account deletion and full erasure/retention audit
  remain untested.
- A supplied 1000-character correlation value was echoed. The bounded-value
  test failed a proposed hardening expectation, not a settled historical size
  contract. Validation/bounds and logging behavior need review in #108.
- Fresh migrations, migration/model drift and EF dependency alignment remain
  blockers: [#111](https://github.com/gouthamganta/woven/issues/111),
  [#115](https://github.com/gouthamganta/woven/issues/115),
  [#96](https://github.com/gouthamganta/woven/issues/96).
- Production frontend routing returned HTML for API requests; disabled auth
  guards permit an anonymous app shell. These remain
  [#113](https://github.com/gouthamganta/woven/issues/113) and
  [#114](https://github.com/gouthamganta/woven/issues/114). The custom QA API
  gateway bypasses the former problem; API passes do not validate production nginx.
- Choice/spend operations previously persisted partial state despite a 500.
  Retry-compatible transactions restore the tested happy path and cap behavior,
  but outer atomicity, lost-commit recovery, refunds and idempotency under faults
  remain open in [#124](https://github.com/gouthamganta/woven/issues/124).
- Frontend production dependency audit reported 14 affected package entries:
  2 critical, 10 high, 1 moderate, 1 low. These are package entries, not 14 proven
  exploitable application vulnerabilities. Runtime reachability and newer fixes
  need retesting in [#125](https://github.com/gouthamganta/woven/issues/125).
- Browser login rendered after its intro and showed expected external-SDK
  failure under the network block. Consent lacked a keyboard checkbox control;
  several controls were below the application's 44-pixel target. Inline-link
  exceptions and actual WCAG conformance are not assessed. Mobile home sampled
  at 1.2 seconds had no visible controls; a longer wait is needed before calling
  that a persistent rendering defect.
