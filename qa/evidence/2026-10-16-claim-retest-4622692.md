## P1: new recovery query binds parameters incorrectly

AfterthoughtService.cs lines 92–98 applies the command API signature to the query API:

```csharp
.FromSqlRaw(sql, new object[] { eventType, id }, ct)
```

FromSqlRaw accepts params object[]; it has no cancellation-token argument. The array and token become two parameter objects. Both interrupted deferred recovery and completed-submission duplicate handling throw:

```
InvalidOperationException: The current provider doesn't have a store type mapping for properties of type 'object[]'.
```

Correct query shape (as already used by the endpoint/integration):

```csharp
.FromSqlRaw(sql, eventType, id)
.AsNoTracking()
.AnyAsync(ct);
```

Keep ExecuteSqlRawAsync's explicit parameter collection plus ct. These APIs have different signatures; the command fix is verified, the new query call is not valid.
