## Executed P1 blockers

1. **CancellationToken still binds as SQL parameter.** Moving it before the timestamp/ID does not fix the overload. Both retry-enabled and retry-disabled integration throw the same store-type mapping exception for CancellationToken. The installed EF Core Relational 10.0.12 API has raw-SQL overloads `(sql, cancellationToken)`, `(sql, params object[])` and `(sql, IEnumerable<object> parameters, cancellationToken)`. There is no `(sql, cancellationToken, params object[])` overload. Claim and reset must pass a parameter collection explicitly.

   Correct shape for claim:

   ```csharp
   await db.Database.ExecuteSqlRawAsync(sql,
       new object[] { DateTimeOffset.UtcNow, afterthoughtId }, ct);
   ```

   Correct shape for reset uses `new object[] { afterthoughtId }, ct`. A PostgreSQL control using this overload, configured retries enabled and a nonmatching synthetic ID, passes. This control is QA code, not an application fix.

2. **Recovery stops at the service.** With synthetic persisted interrupted state (ProcessedAt set, no signal), the updated endpoint passes its new check, then real AfterthoughtService.RecordAsync throws `InvalidOperationException: Afterthought already submitted for this match`. The endpoint does not catch that exception locally. Service lines 87–90 still reject the marker unconditionally. Further down, integration still claims only rows with a null marker and returns on zero affected rows: changing the endpoint/service alone cannot recover an already-marked row. Recovery must distinguish an active processor from an interrupted one without reopening duplicate/concurrent processing.

The interrupted-state fixture is executed against the real handler and service; no process-kill experiment was performed. Static concerns from the prior report remain: claim is committed before effects, loading occurs outside cleanup, and cleanup uses the possibly cancelled request token. Safety completion also cannot be inferred from a matching signal, because safety deliberately produces no matching signal. Design any recovery state for both destinations.
